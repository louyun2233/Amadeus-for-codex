# 原生面板审阅与验收

首次审阅：2026-10-28；发布说明更新：2026-10-31。范围包括原生 Qt 界面、Live2D、聊天与事件恢复、MCP、主动来电、设置、安装检查和现行教程。机身外框、配色、字体方向、开屏与来电画面风格、15:26 比例沿用当前版本。

## 确认并修复的问题

| 问题 | 修改后的行为 |
| --- | --- |
| 事件流断线后收不到完成消息，一直等待 | 原生面板定期补查当前轮次；断线重连立即检查，完成回复只追加一次；75 秒仍无结果时结束等待并尝试取消 |
| 提交尚未返回轮次 ID 时，取消按钮无效 | 记录取消意图，取得 ID 后立即取消；提交失败时保留文字与附件供重试 |
| 本地队列清空后仍可能播放正在合成的旧语音 | 同时清空原生队列、停止当前声音并使旧合成结果失效 |
| 开场白预热期间用户已聊天，之后仍插入开场白 | 用户发送消息或来电出现后，取消这次迟到的开场白 |
| 主动台词生成完毕后不再检查当前状态 | 投递前重新检查用户互动、功能开关、忙碌状态与面板连接 |
| MCP 打开面板还返回旧网页地址，能力工具返回状态而非诊断 | 打开原生窗口并返回脱敏状态；能力工具读取诊断结果 |
| MCP 记忆检索未指定库时跨库查询 | 默认只检索面板记忆，Codex 库须显式选择 |
| 多个窗口之间可能收到不属于自己的回复 | 终态查询与取消检查来源窗口；原窗口离线后不把私有回复广播给其他窗口 |
| 长 URL、文件名被气泡裁切，HTML 片段被当作格式 | 消息按纯文本显示并可在长单词内部换行，保留选择复制能力 |
| 记忆列表横向滚动，难以读完条目 | 按窗口宽度换行，提示信息保留内容与来源 |
| 设置中的输入框过窄、部分后端功能没有原生入口 | 文本字段纵向排列；补齐独立 API、合成模型、铃声音量、MCP 授权、主动间隔和清空语音入口 |
| 刷新状态覆盖尚未保存的音色/模型字段 | 保留用户正在编辑的草稿，保存后再同步 |
| WAV 铃声音量同时软件缩放与播放器缩放 | 每次只使用一种音量缩放，避免重复降低音量 |
| 验证脚本仍在检查停用的网页文件 | 改为原生资源、依赖与服务检查；主检查命令纳入 Python 语法和 Qt 回归测试 |
| 启动时会话列表迟到，可能覆盖用户刚发出的消息 | 用户开始聊天后不再载入启动会话；单句模式只在发送时创建会话，避免积累空会话 |
| 半睁眼表情被当作长时间眨眼，强行睁大眼睛 | 按左右眼分别缩短异常长闭合，保留半睁眼及正常眨眼、单眼动作的开合曲线 |
| 点击空白也触发动作，连续点击反复打断 | 优先使用模型命中区域；无效区域以渲染透明度兜底，增加冷却并避免连续重复动作 |
| 点击表情长期残留，动作与台词情绪不符 | 按头部、身体、轻划和轻抚分组随机选台词，表情与字幕跟随所选台词；结束后逐渐回落，正在朗读时不打断 |
| 原生面板没有使用模型注册表中的布局与参数映射 | 应用缩放、位置、口型、视线及显式头部参数配置；默认模型布局不变 |
| 来电文字左对齐，放大窗口后按钮尺寸不足 | 来电文字水平居中；标志、文字和接听键沿同一中轴排布，调整间距、按钮缩放、玻璃描边及悬停/按下反馈 |

## 本机验收步骤

1. 在最小窗口与放大窗口分别打开对话、记忆和设置页。发送包含长文件名的文字，检查可以换行、选择和滚动；附加图片后用「移除」按钮撤回。
2. 开始生成后取消；发送下一条消息，检查按钮恢复正常。若模型服务不可达，应显示明确错误并结束等待。
3. 在设置中修改音色 ID 但先不保存，再点刷新，检查草稿仍在。测试云端克隆时，ID 和目标合成模型必须对应。
4. 语音播放或合成期间点击「停止播放 / 清空语音队列」，确认后续旧台词不再播放。
5. 开启长期记忆与自动提取，明确告诉角色一项长期信息，待维护结束后检查记忆页和顶部计数。
6. 用 `node scripts/verify-panel.mjs` 检查本机依赖与模型文件；开发修改使用 `npm run check`。没有 Windows 原生依赖的环境会明确跳过 Qt 测试，不能把跳过视为已验证原生功能。
7. 点击角色头部、身体，或从角色身上轻划；检查空白处无反应、连续点击有冷却，表情会恢复。右键菜单提供“轻抚头发”“轻拍肩膀”“逗她一下”和“恢复自然”；前三项使用同一套互动台词，最后一项不发声。所有角色台词仍使用已选语音通道，不播放模型内置 MP3。
8. 在最小、默认和放大窗口检查来电页：`Call from Kurisu.` 应居中，接听键不能与文字重叠，底部圆键仍可拒接。

## 能力边界

- 口型目前为播放期间的近似开合，尚无逐音素口型或音频能量同步。
- 表情与动作受模型提供的参数和文件限制；没有对应资源的表情不会凭空生成。
- 当前本地 Base 克隆没有显式情绪韵律控制；不通过变调改变用户选择的声线。
- Windows 听写需要安装与 `speechInput.lang` 对应的系统识别器及麦克风权限。
- 原生聊天显示生成阶段与完成后的回复，没有逐字流式展示。真实模型服务、麦克风和音色相似度仍需在使用者电脑上验收。

## 存储排障边界

磁盘中的会话文件数量与服务返回的会话列表数量可能不一致。遇到该现象时，应核对运行进程的数据目录、文件读取环境及列表过滤条件，不能直接认定会话丢失，也不要为此合并、覆盖或清空原有数据。有关备份和定位步骤见 [记忆机制与备份](记忆机制与备份.md)。

长期事实与聊天提要分别计数。开启长期记忆和自动提取后，新增信息是否进入长期事实仍需通过实际对话触发提取来验证，不能把提要数量当作长期事实数量。
