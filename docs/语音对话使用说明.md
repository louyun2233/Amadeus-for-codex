# 连续语音对话

包含在 2026-11-07 更新的 v1.0.0 安装包中。之前下载过同版本的用户需要重新下载；升级保留原有语音配置。

## 开始聊天

1. 在设置中开启「本机语音输入」和「语音朗读」，确认原有合成通道可以说话。使用本地克隆时，继续使用当前 Qwen 服务和克隆 ID。
2. 在对话页发送或清空尚未发送的文字、图片，点击麦克风。此时出现语音状态、「打断」和「结束」按钮。
3. 等待「麦克风已就绪，请说话」，再开始说。音量条反映实际输入音量；「听到说话」「正在识别」「已识别」分别表示收到了语音、正在生成候选文字和已得到了听写结果。识别中的文字仍可能改变。
4. 默认保持**直接语音对话**。说完停顿后自动发送并回答，不要求查看文字。也可主动点 **「我说完了，等待回答」** 提前结束本句，按钮会完成正在进行的识别并发送。
5. 等待模型回答。角色使用当前声线朗读全部分段，朗读结束后恢复聆听。已识别、已发送、等待回答和朗读中的状态分别显示。需要进一步核对时才点「文字备选」展开本句文字；校对后发送，下一句仍回到直接语音流程。

### 发言结束方式与灵敏度

在设置中选择「发言结束方式」与「识别灵敏度」，**下一次开始语音对话时生效**：

- **实时语音：直接对话**：默认。识别完成后自动提交，仍可提前点击「我说完了」。不用打开文字预览或逐句手动确认。
- **备选：文字确认后发送**：按需选择。可以分几句表达后修改、确认再提交。它是进一步确定内容的选项，不取代原有的直接语音输入。
- **当前一句的文字备选**：直接语音模式中点「文字备选」，仅对本句展开预览并等待确认；发出后下一句恢复直接语音。若不想处理文字，点「重新说」即可再次用语音表达。
- **灵敏／标准／谨慎**：默认「灵敏」。调整接受听写结果的置信度阈值；灵敏模式保留更多轻声或不确定的结果，也可能增加误识别，因此始终可以核对文字。它不会改变 Windows 全局麦克风音量或克隆声线。

音量条在说话时应有变化。如果一直为零或很低，请检查 Windows 默认录音设备、麦克风权限和输入音量；单纯降低置信度阈值不能放大硬件没有收到的声音。

**没有听清时不会发送空消息。** 尚无完整结果时，候选文字会保留供备选核对，也可以点「重新说」继续使用语音。按需展开的预览可直接编辑，编辑时暂停收音。结束模式时，尚未发送的候选文字会保留到输入框。

同一次语音会话携带最近多轮上下文，可以追问「为什么」「刚才那一点呢」。普通文字聊天的单句开关保持原样，长期记忆继续按自己的开关工作。结束后再点击麦克风会开始新的语音会话；旧内容保留为本机历史，不会自动接回旧通话。

## 打断、暂停与结束

- **打断朗读**：角色正在朗读时点击「打断」。当前音频立即停止，保留这一通对话的上下文，再次聆听。系统先完成停止播放与释放识别器，再打开下一次收音。
- **结束对话**：点击「结束」、再次点击麦克风或按 Esc。正在等待的模型调用会被取消，麦克风关闭，旧识别结果和旧音频不能在之后误发送或误播放。
- **语音结束指令**：正在聆听时可说「结束对话」「结束语音对话」「停止语音对话」「结束通话」或「先不聊了」。整句匹配时在本机执行，不再作为问题发给模型。
- **文字与图片补充**：开始打字或选择图片时暂停收音；发送后仍属于当前语音会话。保留未发送草稿时不会用识别结果覆盖它，清空草稿后可以继续聆听。
- **切换页面**：离开对话页暂停聆听，返回对话页后继续。来电、服务断线、关闭窗口、切换到另一个音频窗口或关闭语音开关时直接结束语音模式，避免后台继续收音。
- **长时间静默**：连续约十次没有识别到有效说话时关闭麦克风。手动模式已有文字时，暂停收音并保留文字等待确认；没有文字时结束模式。使用默认六秒初始静默窗口，通常约一分钟。

本次采用轮流说话：角色播放回复时麦克风暂停。要在她说话时插话，请先点击「打断」；播放期间喊结束指令不能作为打断方式。聆听期间 BGM 临时静音，退出聆听后按原有音量规则恢复，不会保存成零音量。

## 来电接听

点击 **CONNECT** 后返回对话页，显示并优先播放本次来电开场白；其他播报在响铃期间等待，在开场白结束后继续。开场白沿用当前声线，状态栏显示准备和播放状态，失败时会在对话中保留提示。拒接不会播放开场白。

接听不会自动启用麦克风。需要继续直接语音对话时，再点击麦克风；文字校对仍然是备选功能。

## 听写效果与故障

| 现象 | 处理 |
| --- | --- |
| 提示语音朗读未开启 | 在设置中开启朗读，先确认当前克隆服务正常；程序不会为此替换声线 |
| 没有中文听写引擎 | 在 Windows 设置中安装对应语言的语音识别包；默认识别语言为 `zh-CN` |
| 麦克风不可用 | 检查 Windows 麦克风权限、默认录音设备及其他程序是否独占该设备 |
| 同音词或专有名词听错 | 手动模式下可直接编辑预览再发送；自动模式已发送时，也可打字补充「我刚才说的是……」 |
| 能看到声音但没有完整文字 | 等待识别，或点「我说完了」完成当前一句；不确定的文字会保留供确认，不会自动当成成功发送 |
| 回复没有声音或合成失败 | 检查原克隆通道与本地服务。模式会停止并保留文字，避免反复录音或悄悄换音色 |
| 等待模型超时 | 继续沿用对话连接超时与取消机制，检查 Codex/独立模型连接后再开始 |
| 提示识别超过时限 | 自动模式单次约三十秒后停止；手动模式约六十秒后暂停并等待确认。已经得到的文字保留，不自动发送不完整结果 |

Windows 听写的准确率依赖语音包、麦克风、环境噪声和表达内容，不能保证逐字正确。真实系统文件识别测试也观察到同音词误识别，因此界面会回显实际识别文字，而不是将测试文字冒充为识别结果。

## 数据与实现

语音模式仅在点击开启后收音，启动程序不会自动开启麦克风。识别使用原生 Windows `System.Speech`，不将录音上传到 Amadeus HTTP 服务，也不保存原始麦克风音频。识别后的文字与普通聊天一样进入当前配置的对话模型与本机历史；朗读文本进入当前选定的语音服务。是否发往云端取决于用户自己的模型和合成通道配置。

实现复用 `POST /amadeus/chat`、`POST /amadeus/chat/cancel`、SSE 和已有语音合成接口，没有新增浏览器面板或录音上传接口。语音请求携带 `mode: "voice"` 和本次请求编号；续聊需要相同原生客户端及未结束的语音会话。结束请求使用 `voiceSessionId`，不能关闭其他客户端的会话。回复携带实际入队音频 ID，原生端等待全部播放完成，而不是按文字长度猜测时机。

Windows 识别采用 [RecognizeAsync](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.recognizeasync?view=netframework-4.8.1)，手动完成使用 [RecognizeAsyncStop](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.recognizeasyncstop)，取消使用 [RecognizeAsyncCancel](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.recognizeasynccancel?view=netframework-4.8.1)。实时预览使用 [SpeechHypothesized](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.speechhypothesized)，音量反馈使用 Windows 输入音量事件及属性。回归测试使用合成识别事件和实际 Qt 控件，另用静音 WAV 检查真实中文听写和手动结束；这些自动检查不采集麦克风，也不播放测试音频。
