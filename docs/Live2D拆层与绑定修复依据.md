# Live2D 拆层与绑定修复依据

本说明记录官方方法、建模过程与验收范围。新模型作为可选形象随 v1.0.0 提供运行文件，没有替换原默认角色或克隆声线；开发用工程保留在本机。

## 当前结论

常服、实验服、女仆、泳装、浴衣五套素材已通过本机 See-through CUDA 拆层与隐藏区域补画，并由 PSD2Live 生成绑定工程、Cubism 工程和运行文件。当前工程集中在 `local-models/<服装>/runtime`，绑定工程文件名保留 `ai-v9-eyes-only` 标识；早期失败试作已清理，关键问题记录保留，不能与当前工程混用。

按用户后续要求，新模型采用**仅瞳孔跟随**：固定头部及身体的转向参数，保留独立视线、眨眼、眉眼、口型、表情、呼吸与发束绑定。原默认模型继续使用原有跟随方式。真实左右转头的透视没有列为已完成能力。

12 种表情以素材文件夹内的实际 PNG 为参考，分别处理眼睑、眉形、嘴角与脸红。闭眼线重新从同姿势的闭眼原图提取；服装与暴露皮肤的可见颜色恢复为原图，生成内容主要保留在被遮挡区域。每套模型分别检查 79 个原生 SDK 姿势和 13 个实际面板的取景／表情画面；这些检查属于本机技术验证，不能代替用户的画面验收。

头发采用实际遮挡关系：眼白、瞳孔、睫毛、眉毛和闭眼线均位于刘海后方，头饰位于刘海前方。原画中透过刘海绘制的线条不作为本模型的穿透效果保留。虹膜仍由独立眼白遮罩裁剪，不能为了遮头发而破坏视线绑定。

当前五套模型已按用户确认的方案纳入 v1.0.0，界面只显示各服装名称。发布的是运行所需的 MOC3、贴图、表情与动作，开发工程及诊断缓存不随包提供。

## 官方拆层方法如何对应本次问题

### 1. 从完整形象开始验收

先保留原图和独立的拆层工程，再输出合并为单层部件的导入 PSD。原画、拆层 PSD 与导入 PSD 分开保存。将所有部件在默认状态重新叠合，必须仍是完整、位置一致的人物。

官方依据：[素材分离](https://docs.live2d.com/4.2/en/cubism-editor-manual/divide-the-material/)、[导入 PSD 的制作](https://docs.live2d.com/en/cubism-editor-manual/reimport-psd/)。

### 2. 需要补画遮挡部分，扩大贴边不能代替补画

前发、侧发、后发应分别处理。发束下方、颈部与衣领后方、被虹膜挡住的眼白都必须补足，否则一移动就会断开。宽大的原图底层和图层重叠可以辅助验证，但不能代替每个独立运动部件完整的隐藏区域。

本次已经发现：粗略的多边形或按颜色阈值分离，容易把刘海线、皮肤和睫毛混在一起。新补画的脸底只用于隐藏区域，不能把配准尚有偏差的生成图直接当作人物。常服第三、四版眼部拆层仍有明显色块/遮挡错误，已列为不合格，不能取用。

官方依据：[插画加工](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)。

### 3. 眼白、虹膜、睫毛必须分开

眼白要补足虹膜后面的区域，虹膜移动时只允许露出干净眼白。虹膜不能带着周围皮肤和刘海移动。完整闭眼线可参考原作者同姿势的闭眼素材，但不得让原图睁眼线、补画闭眼线、残留刘海线同时出现。

本次修正了一个素材采样错误：早期眼白补画取样含有深色眼线，已换用不含眼线的小块并匹配原图眼白颜色；仍需继续精修轮廓，不将颜色阈值结果视为精确遮罩。

### 4. 用正确遮罩处理眼部边缘

官方解释，遮罩半透明边缘可能让底层颜色透出来。简单形状可复制遮罩、略微放大、将复制件不透明度设为 0%，并保持同样变形，再由复制件提供裁剪。这里的“不透明度为 0%”与直接隐藏或删除遮罩不是一回事。

已按此方法制作独立的透明扩大遮罩试验。细线仍存在，所以尚不能断言当前眼部问题只由这一机制造成。也要检查眼白本身的素材边界和残留线条。

官方依据：[裁剪遮罩与白边](https://docs.live2d.com/en/cubism-editor-manual/clipping-mask/)。

### 5. 嘴部不能整体带着一块矩形皮肤变形

唇线、嘴内与嘴周肤色应分别处理；嘴内需留出遮挡余量。把带皮肤的矩形裁剪交给自动嘴部识别，会让皮肤边界或多余内容参与变形。本次关闭了自动唇线生成，并将嘴部皮肤矩形换为原画口部笔触与独立的开口区域，原生运行时已不再显示原来的嘴部方框。

官方依据：[插画加工中的嘴部处理](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)。

### 6. 网格、贴图与最终运行时都要检查

网格太疏时，相邻切片对同一个非线性变形器的近似也可能不同。当前对大部件做了两次细分以减少错位，但密度增加不能解决切错图层或错误的变形器关系。贴图打包还需检查重叠、越界、间距与缩放质量。

官方依据：[准备移动插画](https://docs.live2d.com/en/cubism-editor-tutorials/import/)、[编辑贴图集](https://docs.live2d.com/en/cubism-editor-manual/texture-atlas-edit/)。

运行时验证脚本应按运行库说明保存静态测试参数，再执行更新、绘制，并检查实际参数值。已改用 `SetSaveParamById` 设置测试姿势，持续绘制，不以一次帧缓冲截图判断主体是否消失。此前“闭眼主体消失”的判断没有在连续帧像素检查中复现，已撤回这一确定性结论。桌面截图可能被其他窗口覆盖，必须区分截图问题与模型问题。

运行库作者示例：[面部参数绑定](https://github.com/EasyLive2D/live2d-py/blob/main/examples/main_facial_bind.py)。此方法用于静态测试，不应直接替换现有面板的表情逐帧合成逻辑。

官方素材分离 Photoshop 插件支持半自动抠取、颜色填充和透明区域填充。但官方列出的条件包括 Photoshop 2024/2025、Cubism Editor 及已激活的 Cubism PRO 许可，试用期间也可使用。当前没有确认本机具备这些条件，所以没有下载安装或代为激活。

[下载与使用条件](https://docs.live2d.com/en/cubism-editor-manual/material-separation-ps-plugin-download/)、[操作方法](https://docs.live2d.com/en/cubism-editor-manual/material-separation-ps-plugin-manual/)。

## 本机文件

当前模型工程位于项目忽略目录 `local-models`，按 `common`、`lab`、`maid`、`swim`、`yukata` 分类。各目录保留 `.psd2live` 工程、Cubism 工程、修正后的分层 PSD、运行文件及关键原生检查画面。建模工具及精简 Java 环境位于 `local-models/tools/psd2live`，不依赖已清理的旧构建缓存。

本机角色库的运行副本默认位于用户主目录 `.amadeus/media/models/kurisu-authored-v9`；显式指定媒体目录或数据目录时跟随相应配置。选择记录与旧版模型均保留；模型升级不修改语音配置。开发素材、授权资料和检查日志不会因本次修改自动进入发行包。
