# 原生交互与情绪说明

更新日期：2026-11-03。改动在原生 Qt/OpenGL 面板内实现，沿用当前翻盖手机外观。

## 对话和待机

| 场景 | 可见反馈 |
| --- | --- |
| 在输入框打字、使用麦克风 | 倾听姿态；停止打字约 4 秒后回到待机 |
| 发出消息、等待模型回答 | 思考姿态与视线，直到回复、取消或失败 |
| 收到回答 | 优先使用回复中的情绪标签，缺失标签时从文本推断；关闭语音也生效 |
| 朗读 | 使用每段台词的情绪；音频实际结束后停止口型开合，约 0.65 秒衔接期后平滑恢复初始表情 |
| 只有文字回复 | 情绪默认保持约 3 秒，最后约 0.6 秒减弱，随后恢复初始表情 |
| 回复或互动结束 | 恢复初始表情，取消旧的长时间余绪；点击互动结束不会重新显示之前的回复表情 |
| 普通待机 | 自然状态留有停顿，再低频切换轻度状态；语音结束后至少留约 6 秒自然间隔，不无故发怒或自动发声 |
| 回复失败 | 短暂失落反馈，约 4 秒后恢复 |

情绪不是额外的一次模型调用。回复解析保留合法情绪标签；缺失标签时，普通技术失败描述使用思考表情，安慰使用温和表情，不再因为出现“失败、错误、不能”就自动生气。人物区下方的状态栏对应渲染器当前实际状态，思考与倾听显示活动名，其他情况显示情绪。

默认模型虽然列出笑眼、眉形和眉角等参数，但实际网格不会随其中几项变化。现在主要由确实有效的眼睛开合、眉高、嘴角、嘴部开合、视线及头部姿态共同表达情绪，并限制原动作/表情的叠加，避免原本已经撇嘴的表情抵消新的微笑。`f01` 是空表情，模型也没有独立脸红参数，因此害羞使用避开视线、低头及轻微笑意表达，不承诺脸红贴图效果。Windows 减少动态效果仍保留面部情绪，只减少头部和身体的额外移动。

面部叠加只作用于当前渲染帧，不写回 SDK 的持久参数。旧实现使用 `SetParamById` 恢复已经叠加表情的值，会将眼睛的缩小系数逐帧累乘；现使用临时差值覆盖，避免眼睛越来越闭。左右眼分别限制异常长闭合，情绪切换不重置恢复计时；短暂眨眼、闭眼动作和半眯眼表情仍保留。

眉毛、嘴角、日常眼睑和说话口型在原模型动作与情绪叠加完成后，按实际帧间时间平滑过渡，减轻思考、回答、朗读结束及待机之间的突变。连续相同情绪不重启动作中的表情，也不反复重置口型节奏。短暂眨眼与单眼眨眼沿用各自的开合曲线，不被通用缓动拉长；鼠标视线与头部跟随不增加额外的平滑层。

### 新模型的眨眼与自然恢复

五套本机候选模型启用 `Amadeus.EyeBlink: "independent"`。静态表情决定自然眼型，自动眨眼用独立的短时倍率控制：合眼约 55 毫秒、闭合停留约 25 毫秒、重新睁眼约 120 毫秒。先平滑眼型，再应用眨眼，避免表情缓动把闭眼拉长。窗口暂停后不补演过期眨眼，表情切换不重启当前眨眼，单眼动作也不叠加一次自动双眼闭合。原默认模型保留自己的眨眼路径。

新模型的表情强度会同时作用于眼睑、眉毛、嘴角和脸红；短暂表情退出时，可见表情也逐渐恢复。取消原先约 30 秒的余绪，防止互动后重新显示旧回复的嘴型。语音结束后先恢复初始嘴型，保留自然间隔后才允许下一次轻度待机表情。

「恢复自然」会清空 SDK 的表情队列与预览状态，保留面部平滑器，让过渡从当前画面衔接。旧 Cubism 2 渲染路径还会在每次 SDK 更新前准备中性的面部基值，再由 SDK 计算本帧动作、眨眼和表情，避免旧眉形、撇嘴或眼睛倍率留在持久参数中。此步骤只处理面部通道，不重置鼠标、头部、身体或物理跟随参数，也不将本帧渲染结果写回基值。

### 情绪如何展开

18 种情绪各有短时编排：先出现眉眼或视线反应，头部随后跟进，最后回到可以自然停留的表情。相同情绪的连续语音沿用原进度；点击反馈开始后接上同一句语音，也不会再惊讶或转头一次。新的输入或情绪从当前姿态平滑接替。

| 状态 | 动作顺序 |
| --- | --- |
| 害羞 | 短暂抬眉，目光躲开；轻转头后回看，嘴角逐渐放松 |
| 有点不满 | 先收眉侧目，再轻转头，随后松开眉眼、收回视线 |
| 开心、兴奋、得意 | 分别侧重微笑倾头、短促抬眉和轻抬下巴；起初的张嘴会收回 |
| 惊讶 | 短暂睁眼抬眉、张嘴，随后收口并保留轻度好奇 |
| 放松、低落、失落 | 用不同的眉高、视线落点和头部回落节奏区分，避免始终挂着同一张脸 |
| 倾听 | 关注对方、轻点头后回正；持续输入时偶尔再轻轻回应 |
| 思考 | 先偏移目光，头部稍后跟进；回到关注状态，长时间等待时低频短暂移目 |
| 待机 | 延续上一轮的轻度情绪，之后低频微动作；不反复摇头，不随机进入强烈愤怒或害羞 |

说话口型的张开幅度可以受情绪影响，但情绪不会将嘴部锁死在张开状态。嘴唇仍能闭合并有轻微停顿；这仍是播放期间的视觉口型，不是逐音素或音频能量同步，不改变合成音频。

### 语气与表情同步的边界

语音表情从播放器实际开始播放时起算，不能在排队或等待合成期间提前演完。同情绪的相邻片段沿用进度；情绪发生转折时，从对应片段出声时开始新反应。文本模式仍即时显示表情。句内后置标签只作用于它后面的文字，不回填到前一句；中文翻译中的标签不覆盖日文朗读段落。

原克隆使用本地 Qwen Base 路径。当前本机服务的 `generate_voice_clone` 调用不传入情绪指令，表情标签因此不等于语音韵律控制。人设提示要求台词本身用自然措辞、句尾和标点体现态度，但这只能影响新回复的文字，不能保证合成器产生明显的情绪韵律，也不会重制已有短句缓存。要实现可控的开心、害羞、愤怒等声音表演，还需要单独验证支持原声线参考音频的情绪合成方案；当前没有实现，不能用变速、变调或换声冒充。

## 人物交互

- 轻点头部、身体：不同动作、短字幕与台词。
- 从人物上轻划：拖动逗弄反馈，台词与所选情绪同步。
- 按住头部至少约 0.65 秒再松开：轻抚反馈。
- 右键：深红色互动菜单，与手机界面同色；提供“轻抚头发”“轻拍肩膀”“逗她一下”“恢复自然”。前三项走同一套人物反应、字幕及已选克隆语音流程；“恢复自然”清除临时表情与动作，平滑回到自动待机，不播放声音。
- 空白处不触发角色反应；顶部仍用于拖动窗口。
- 操作说明：点击人物区下方的“互动说明”，在下方面板内查看手势与三个快捷动作；点击“收起说明”或按 Esc 返回原页面，保留未发送文字。

交互带冷却，思考和朗读不会被点击打断。关闭语音时仍显示字幕与表情；开启语音时仍由当前配置的语音服务朗读。固定台词定义在 `persona/<角色>.json` 的 `tapReactions`，可选 `cn` 字段用于字幕、`gestures` 字段用于 `head`、`body`、`swipe`、`pat` 分组；没有这两个字段的旧角色文件仍可使用。

默认角色提供 **72 条互动台词**，四种动作各 18 条，整体覆盖 18 种情绪。每次点击从当前动作的可用台词中随机抽取；一轮内不重复，抽完再开始下一轮，并在有其他选择时避免两轮交界连续重复。新准备好的语音会加入抽取范围。台词选定后同步切换表情和中文字幕，不再被少数预设情绪限制。右键菜单的互动也使用同一台词库；未配置某种动作时只回退到无动作标签的通用台词，不借用其他动作的内容。

菜单不再列出 `f01`、`tap_body` 等内部文件/动作标识。倾听、思考或朗读时菜单与说明中的动作按钮提示忙碌状态，并暂时禁用互动；即使打开期间开始对话，动作执行时也会再次检查。

人物区域不再弹出随鼠标出现的长段说明。情绪状态、操作说明和互动字幕都放在人物显示区之外；展开说明不改变人物区大小。字幕按窗口宽度换行，长内容在最多 62 像素高的区域中滚动查看，避免向上遮住脸或撑大手机。来电时收起说明与字幕，沿用完整来电画面。

### 点击语音的等待

选用本地 Qwen 克隆且开启语音时，面板在空闲时逐条准备固定点击台词，复用服务端无损 WAV 缓存；开场白准备、聊天和正在播放的语音优先。点击时优先选择该动作中已准备好的台词，在本机直接播放，不再等待 `/say` 事件往返或现场合成。后台准备本身不会发声，也不修改音色配置。

首次安装、改动台词或更换克隆后，需要先准备语音。如果当前动作尚无可用语音，会显示“互动语音准备中”，表情与字幕仍即时响应；准备完成不会补播旧点击。连续点击不积压语音，新聊天、来电、其他播报、静音或声线配置改变会撤销当前点击语音。排入播放线程后超过 1 秒尚未开始的点击也会丢弃。

仅对点击语音，播放器可跳过可确认的 PCM16 开头近静音：所有声道振幅不超过 16/32768，且持续至少 200 毫秒时，保留起音前 100 毫秒，最多跳过 1 秒。检测到轻微起音、非支持格式或损坏文件时保留原起点。缓存音频字节不变，不剪切人声、不变调、不加速、不更换克隆。正常聊天、开场白和铃声不应用此跳过规则。

内存准备上限为 96 条不同台词、48 MiB；后台同时最多请求一条，交替准备不同动作与情绪，避免先准备完头部台词再处理其他动作。失败按 30/60/120 秒退避，关闭语音不继续预热；更换音色或台词后拒绝旧配置的迟到结果。此优化只自动预热本地克隆，不额外发起云端批量合成。本地缓存短句播放结束后即可再次点击发声，不再额外等待 3.5 秒；播放期间仍不叠加或排队，其他合成服务仍保留请求防抖。

## 跟随与声线

眼睛、头部和身体使用同一个按时间计算的鼠标平滑器，面板内外保持同样的响应速度；超出显示区时按边缘处理。绕开 SDK 额外的慢速拖动缓动，减小待机动作与左右转头互相拉扯。Windows 关闭界面动画时减少额外待机动作。

面部情绪与本地 Base 克隆的声学参数分开：不向本地克隆增加情绪指令、变速或变调。同一句话使用相同克隆音色时，表情变化会复用原有无损 WAV 缓存。设置页关闭下拉框时忽略滚轮，防止滚动页面意外更换合成服务。

### 句中中断与播放停滞

本地 Qwen 合成现通过 SSE 接收原始 WAV 数据，必须收到 `speech.audio.done` 且 WAV 结构完整才允许播放和缓存。HTTP 200 本身不能证明合成成功；中途错误、断流或损坏片段会明确报错，不把半句话写入新缓存。不支持该完成事件的旧服务会提示错误，不退回无法验证完成状态的原始流。此修改不更换克隆，也不修改 PCM 采样、语速或音调。

### 长回复的分段与衔接

本地克隆的每个合成片段最多 80 个 Unicode 字符，优先在句末、逗号或空白处切分，并保留所属情绪。回复不再因为超过 24 句而截去末尾；一条回复的语音片段整体进入队列，队列最多容纳 512 条、共 64000 个文本字符，超限时明确提示，避免悄悄丢掉前半段。该限制针对待播内容，不限制聊天文字显示。

当前段开始实际播放后，原生面板提前准备下一段本地聊天语音；最多同时预取一段，取回结果不能超过 8 MiB。准备和等待均在后台线程进行。取消、新聊天、来电、关闭语音或切换声线会撤销旧播放与预取，旧请求即使稍后返回也不会补播。已预取的片段直接接续播放；如果下一段合成所需时间超过当前段的播放时间，仍会有等待，不能保证所有负载下都无停顿。

不超过 80 字的短句继续使用原缓存键，已有点击台词不批量重生成。长段改用分段缓存版本，避免继续复用旧的一次性长段结果；旧文件保留。需要返回单个 WAV 的其他调用会在全部子段成功后拼接原始 PCM，格式不一致时拒绝拼接，不交叉淡化、不重采样、不变调，也不缓存只完成一部分的长段。

Windows 播放器检查播放位置与时长；位置持续 3 秒不前进或超出应有播放时间时停止并提示，不自动重播卡住的句子。停止请求不再等待音频设备后才返回界面线程，避免停止语音时冻结动画。上一段媒体设备未释放时不会叠加启动另一段；迟到或重复的完成通知不能结束当前新语音。

已有 72 条互动语音逐条检查均未发现削波、帧格式损坏或完全重复的可听片段，因此没有清空缓存或重新克隆。部分台词本身有约 1 秒停顿；数字统计不能判断所有主观失真或确认旧音频在语义上说完。若某句仍每次在同一处异常，应定位那一条音频，而非批量重生成全部声线。

## 验证

2026-11-01 改版已用真实模型检查 18 种情绪和倾听状态，并逐帧核对眼部恢复。另检查 270×468 与 450×780 两种窗口下的默认画面、说明顶部与底部、长字幕顶部与底部和来电画面，共 12 个场景：操作按钮可见，长内容可纵向滚动，没有横向溢出，说明与字幕均位于人物区域之外。真实 OpenGL 跟随短测约 62.6 帧/秒，帧间隔第 95 百分位约 16.8 毫秒。

本轮检查：437 项 JavaScript 测试中 436 项通过、1 项跳过；原生回归共 126 项通过，覆盖随机抽取、字幕表情同步、眼部参数不累积、逐眼恢复、断流拒绝缓存、长回复不截尾、分段原始 PCM 保持一致、预取复用与取消、设备停滞和取消播放。真实模型的 18 个动作加 3 组眼部情绪序列均恢复睁眼；固定 60Hz 探针中最长连续近闭合约 200 毫秒。上一轮五组状态切换探针中，最终面部参数首帧跳变量约降至未平滑时的五分之一；这不代表所有动作都达到相同的主观改善幅度。

上一轮真实 Qwen 服务使用原克隆完成一段 182 字日文，分成 80、78、24 字三段，总计约 30 秒音频，合成共约 8.9 秒。三段均收到完成事件，全文保留；验证使用隔离缓存，未替换用户已有的 72 条互动语音或参考音频。该检查确认传输与音频结构完整，不代替对发音、韵律和音色的试听验收。

随后用这三段克隆 WAV 进行 Windows 播放器静音连续播放，每次模拟 300 毫秒取回延迟；后两段均在上一段结束前准备完成，播放器事件测得段间间隔约 43、34 毫秒，无播放错误。这验证了预取与连续播放链路，不是扬声器实际出声的延迟测量；原音频内已有的自然停顿仍保留。

上一轮在已有磁盘缓存时，原生面板自动载入 72 条语音约需 476 毫秒；静音播放测试中，三次点击到 Windows 接受播放命令约 49～129 毫秒，均正常结束。这不是扬声器可听到人声的端到端测量，首次合成时间也不包含在内。真实模型跟随测试约 63 帧/秒、帧间隔第 95 百分位约 17 毫秒；已检查闭眼及恢复画面。这些是一台电脑上的短时结果，实际负载仍可能影响表现。麦克风识别效果和克隆音色听感需在本机验收。

依次验证：打字、发送、关闭语音后查看回复表情、静置十几秒观察待机、轻点/轻抚人物、快速左右移动鼠标并移到面板外。语音应始终使用自己选定的克隆音色；听到系统声线时先核对「设置 → 合成服务」及运行状态，不能仅检查磁盘配置。
