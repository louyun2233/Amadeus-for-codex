# 背景音乐与场景

在原生面板的「设置 → 角色素材」选择音乐、调整音量或更换人物背景。支持从文件导入音乐和图片。默认复制到 `%USERPROFILE%\.amadeus\media`，选择记录保存在该目录的 `library.json`，不写入 Git 仓库。指定 `AMADEUS_MEDIA_DIR` 时使用该目录；指定 `AMADEUS_DATA_DIR` 时继续使用其下的 `media`。

v1.0.0 随附 14 首音乐与 8 张场景。安装器或首次打开面板时自动校验并复制到稳定媒体目录，选择器直接可用。新安装默认曲目为 `bgm10`，循环播放，默认音量 12%，界面上限 30%；角色朗读时降至设定音量的四分之一，来电期间音乐静音，结束后恢复。音乐开关独立于角色语音开关。关闭面板停止音乐，升级保留已有选择。

人物背景默认保持黑色；可选择场景，或手动导入 PNG、JPEG、WebP、BMP。背景按比例铺满人物显示区域，不改变手机外形，也不覆盖来电画面。选择「黑色背景（默认）」恢复原外观。

背景下拉框选定后立即更新人物区，下方显示缩略图和“已应用”反馈。图片丢失或无法解码时保留原背景并提示重新导入；保存失败时仍显示新背景，并提示重新打开后可能恢复旧设置。更换背景不再重新启动音乐。检查覆盖 8 张场景连续切换、恢复黑底、手动导入、选择记录重载、文件缺失和保存失败。

背景与 Live2D 共用 OpenGL 画布时，Qt 的图片绘制器必须保持到原生模型绘制结束，并用 `beginNativePainting` / `endNativePainting` 切换。此前提前结束绘制器，会出现“屏幕黑底、截图却有背景”的误判。验证时不能仅调用窗口截图接口：在已安装原生运行环境、模型且桌面可见的 Windows 上，运行 `.native-venv\Scripts\python.exe scripts/verify-background-render.py`，脚本直接捕获屏幕像素，检查两种背景和恢复黑底，不播放声音。

Windows 打包应用可能把 AppData 中的文件重定向到自己的缓存，造成独立启动与 Codex 连携启动看到不同的素材库。默认媒体目录已移至用户主目录，首次运行自动从原 AppData 素材库复制条目、模型配套文件和选择记录，保留旧文件。绝对路径、`..` 和越过素材目录的文件链接仍被拒绝。

保存使用跨窗口写入锁和原子替换，保留 `library.previous.json`；旧窗口修改音量等字段时会保留其他窗口新增的素材。素材库损坏时优先读取有效备份，没有有效备份时拒绝用空目录覆盖原文件。音乐、角色和背景共用一致的列表刷新逻辑。

新安装的来电音乐为完整的 `bgm13`，约 111 秒，使用独立铃声通道循环播放，接听或拒接即停。原 OGG 保留，来电副本转换为 Windows 原生媒体驱动兼容的 MP3，登记在素材库 `ringtone` 字段；音量继续由「铃声音量」控制。此设置不改变角色克隆声线。升级保留用户原有铃声，未配置本地来电音乐时继续支持数据目录 `sounds/incoming.*` 的兼容入口。

维护时运行 `npm run check`。原生测试覆盖三类选择框的鼠标、键盘、保存、重载，跨启动环境的素材迁移、多个窗口保存时保留新增素材、损坏文件恢复及写入失败保护。实际窗口和静音媒体驱动检查用于补充验证，不能仅用程序赋值作为切换成功的依据。

## 新角色的实际状态

现有 Live2D 仍为默认角色，已有克隆声线保持不变。常服、实验服、女仆、泳装、浴衣原本为合成 PNG，已完成 GPU 拆层、遮挡区域补画和绑定，其运行文件随 v1.0.0 分发。在「设置 → 角色素材 → 角色形象」中只显示各服装名称，不附加功能或验收状态的字样。

选择服装后可切换「正常／大头」取景；选择默认形象即可恢复原模型。取景由各模型自己的头部和头饰范围计算，不采用所有服装共用的固定放大倍数。关闭重开后保留所选形象和取景，添加新模型不会自动切走原默认形象。

新模型按用户选定的方案固定原始头身姿态，仅让瞳孔跟随鼠标；独立眨眼、眉形、眼型、口型、脸红和发束绑定保留。12 种表情参考素材中的其他图片，通过渐变切换，覆盖聊天情绪与互动反应。刘海会遮挡眼睛、睫毛、眉毛及闭眼线。

眼部修订 2 将静态眼型与约 200 毫秒的自动眨眼分开，校正了开心、困倦、俏皮等表情长期半闭眼的问题，并缩短表情文件的交接时间。瞳孔网格、纹理、头身绑定和取景不变。新模型的 SDK 表情会随情绪强度减弱，余绪结束后先回自然状态；手动恢复也会清除旧预览。眨眼与自然恢复的具体行为见 [交互与情绪说明](交互与情绪说明.md#新模型的眨眼与自然恢复)。

本机工程目录的 `local-models/tooling/calibrate_eyes.py` 保存眼部修订配方。重新从建模工具导出后，用项目原生 Python 运行该脚本可重设表情与眨眼文件；它只处理已登记的五套模型，保留一次备份，不更换模型选择或声线。修改前仍应保全自己新导出的工程。

嘴部修订清理了五套新模型张嘴贴图周围的杂边，修正小幅开口关键帧中的网格翻折，并缩短闭嘴／张嘴贴图交接的范围，避免叠出两套轮廓。说话中的停顿允许开口值回到零。透明图集在原生纹理缩小时会把透明像素的黑色混入口型边缘，因此导出后还需运行本机 `local-models/tooling/prepare_mouth_atlas.py` 的处理函数：只延伸完全透明像素下的 RGB，不改变透明度、可见像素或 UV。不能通过整张图预乘 Alpha 来代替此步骤。

重新导出嘴部时保留当前模型入口、独立眨眼文件和 12 种表情，按本机 `local-models/mouth-repair/prepare_candidates.py` 的流程完成贴图修订、交接关键帧和图集边缘处理。验证须覆盖连续说话中的小幅开口、笑脸／撇嘴、语音暂停和结束复位；编辑器预览正常不能代替原生 SDK 的实际画面。

当前五套模型已按固定头身、瞳孔跟随的方案纳入 v1.0.0，不提供真实头部转向的透视。发行包在 `assets/media/models` 提供运行文件；最新编辑工程、分层 PSD、关键画面与工具保留在本机忽略目录 `local-models`。这些开发工程不随包发布。

模型检查包括眨眼不同阶段、瞳孔上下左右移动、口型、各表情与头身转向抑制。嘴部修订额外覆盖 120 个原生口型姿势、4,320 帧连续说话和 102 项表情恢复；实际正常／大头取景、切换与保存也已检查。模型能加载只属于必要条件，仍需核对实际画面。
