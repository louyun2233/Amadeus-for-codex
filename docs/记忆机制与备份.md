# 长期记忆、备份与故障恢复

## 两种记忆不要混用

Amadeus 面板对话使用 `panel` 命名空间；Codex 任务通过工具显式写入的记忆使用 `codex` 命名空间。两者默认不互相注入。记忆文件位于 `%LOCALAPPDATA%\Amadeus\memory\panel.json` 和 `codex.json`；如果设置了 `AMADEUS_DATA_DIR`，则以该目录为准。会话历史另存于 `sessions/`，不是长期记忆。

长期记忆与自动抽取均默认关闭。开启后，自动抽取只读取用户发言，并要求候选事实能从原话找到依据；模型回答、猜测、提问不会直接成为用户事实。聊天提要单独标为 `recap`，仅供衔接最近的对话，不作为已核实事实注入。旧版保存为 `fact` 的 `source: conversation` 提要也按提要处理。

召回会按本次问题检索相关记忆，不再把最近八条无关内容固定塞进每次提示词。中文检索使用相邻双字片段，减少单个常用汉字造成的误命中。自动抽取依然可能漏掉含蓄表达或复杂纠错；重要事实可通过明确的“记住我……”表达并在面板记忆列表核对。

单句模式下每次回复结束都会检查用户原话中的长期事实，包括持续进行的研究、项目与目标；没有长期事实的闲聊不会额外调用模型。直接问“你还记得我吗”等概览问题时，即使问题没有提到具体关键词，也会尝试取最近的长期事实。面板状态栏把长期记忆和对话提要分开计数：旧版标成 `fact`、来源却是 `conversation` 的条目仍是提要，不能当作已核实事实。既有聊天记录不会在升级时自动重新提取为事实；需要保留的重要信息可在新对话中明确告诉 Amadeus，并在记忆页核对。

开启单句模式时，重新打开面板会从空白对话开始，不会恢复上轮未结束的消息。历史会话仍保存在本机 `sessions/`，可用于备份与诊断；关闭单句模式后才会继续未结束的会话。

`memory.maxPerNamespace` 现在只是旧配置兼容项，不再触发长期事实的自动淘汰。普通事实、摘要和更正历史会保留到用户主动删除；短期聊天提要最多保留最近三条。更正后的旧事实保留在磁盘供审计，但默认不参与召回。

## 日常备份

1. 在面板“记忆”页点击“导出”，保存 `amadeus-memory.json` 到私人目录。这个导出包含 `panel` 和 `codex` 两个命名空间，可能含有敏感聊天内容，绝不可放进 Git 仓库或公开发行包。
2. 关闭 Amadeus 后，按需额外备份整个 `%LOCALAPPDATA%\Amadeus\memory` 和 `sessions`。文件若受 Windows EFS 加密，普通复制可能失败；可在已授权的本机账户内读取文件内容后另存，并确保备份目录权限合适。
3. 每次写入记忆前，程序会将上一份有效的记忆文件保存在同目录的 `.json.bak`。主文件损坏时会读取这份备份；如果主文件和备份都损坏，会报错并停止写入，不会把旧记忆当作空文件覆盖。`.bak` 只保留最近一次有效状态，不能替代定期导出。

主动删除单条记忆、按词遗忘或清空命名空间时，程序会移除对应的自动 `.bak`，避免已删内容从自动备份恢复。用户自行保存的导出、Windows 文件历史记录以及外部备份不会被程序删除，须自行管理。

## 发现“记忆消失”时

先不要重复安装、清空记忆或覆盖 JSON。分别记录面板“记忆”页可见条数、`memory/*.json` 的条数、是否存在 `.bak`，并检查当前 daemon 的数据目录是否与查看的目录一致。若运行中服务导出的内容和磁盘内容不一致，应先把两边分别备份，再排查进程与数据路径；**不要直接把其中一份覆盖另一份**。

如果主文件损坏而 `.bak` 可用，程序会用备份提供读写；这最多恢复到上一次成功写入之前。要人工恢复更早的状态，请先停止 Amadeus，另存现有文件，核对导出的命名空间、时间和条目后再决定如何合并。自动恢复不做跨文件合并，也不自动复活用户主动删除的内容。

源码与发行 ZIP 不包含任何安装者的记忆或备份文件。发布前运行 `npm run check` 和 `npm run dist`，仅上传白名单生成的发行 ZIP。
